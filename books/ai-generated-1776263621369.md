# adb push
> 将本地文件推送到 Android 设备

## 1. 命令简介 (Introduction)  
`adb push` 是 Android Debug Bridge（ADB）提供的文件传输指令，用于把电脑（主机）上的单个文件或整个目录复制到已连接的 Android 设备（或模拟器）内部的指定路径。常用于：

- 将调试资源、配置文件、APK、脚本等快速放入设备中  
- 在没有 USB 存储或网络共享的情况下进行离线文件部署  
- 配合 `adb shell`、`adb install` 等命令完成完整的调试/测试流程  

> **前置条件**：设备已通过 USB 或 Wi‑Fi 正常连接，`adb devices` 能看到对应的序列号；目标路径在设备上具有写入权限（如 `/sdcard/`、`/data/local/tmp/` 等）。

---

## 2. 语法与参数 (Syntax & Parameters)  

```
adb push [options] <local_path> <remote_path>
```

| 参数 / 选项 | 说明 |
|------------|------|
| `<local_path>` | 本地文件或目录的完整路径。可以是相对路径或绝对路径。若是目录，`adb push` 会递归复制目录结构。 |
| `<remote_path>` | 设备上目标路径。若目标是目录，文件会保留原始文件名放入该目录；若目标是完整文件名，则会覆盖或创建该文件。 |
| `-a` | **保留时间戳**：将本地文件的修改时间同步到设备端（默认不保留）。 |
| `-z` | **压缩传输**：在传输过程中对数据进行压缩，适用于大文件或慢速链路。 |
| `--sync` | **同步模式**（仅在部分 ADB 版本中可用）：只复制本地比设备新或不存在的文件，类似 `rsync` 的行为。 |
| `-p` | **保留权限**（在 Android 7.0 以上的 `adb` 中可用）：尝试保持文件的原始权限位。 |

> **组合使用**：可以同时使用 `-a -z`，如 `adb push -a -z src/ /sdcard/`，即在压缩传输的同时保留时间戳。

## 3. 常见用法与示例 (Common Use Cases & Examples)

| 示例 | 命令 | 说明 |
|------|------|------|
| **1. 将单个文件拷入 SD 卡根目录** | `adb push myapp.apk /sdcard/` | 把本地的 `myapp.apk` 复制到设备的外部存储根目录，文件名保持不变。 |
| **2. 把整个目录递归推送到设备的临时目录** | `adb push -a -z ./config/ /data/local/tmp/config/` | 将本地 `config` 目录（含子目录）压缩后传输，并保留每个文件的修改时间戳。 |
| **3. 只同步更新的文件**（需要 `--sync` 支持） | `adb push --sync ./assets/ /sdcard/assets/` | 只把本地 `assets` 目录中比设备上新或不存在的文件复制过去，适合频繁增量更新。 |
| **4. 推送脚本并保持执行权限**（Android 7+） | `adb push -p ./run.sh /data/local/tmp/` <br/>`adb shell chmod 755 /data/local/tmp/run.sh` | `-p` 尝试保留原始的可执行位，随后通过 `chmod` 确认权限，使脚本可直接运行。 |
| **5. 将大文件通过压缩加速传输** | `adb push -z large_video.mp4 /sdcard/Movies/` | 对 `large_video.mp4` 进行压缩后传输，适用于慢速 USB 或 Wi‑Fi 连接。 |

## 4. 注意事项 (Notes / Gotchas)

1. **目标路径的写权限**  
   - `/sdcard/`（外部存储）对普通用户默认可写。  
   - `/data/`、`/system/` 等内部路径需要 root 权限或使用 `adb root`（仅在用户调试版或已解锁的设备上可用）。

2. **目录递归行为**  
   - 当 `<local_path>` 为目录时，`adb push` 会自动递归复制子目录和文件。  
   - 若 `<remote_path>` 指向已存在的文件而不是目录，传输会失败并提示 “remote object is not a directory”。

3. **文件名冲突**  
   - 同名文件会被直接覆盖，不会提示确认。请提前确认目标路径或使用 `adb shell ls` 检查。

4. **时间戳与权限**  
   - `-a` 与 `-p` 只能在支持的 Android 版本上生效（Android 6.0 以后对时间戳支持较好，权限保留在 Android 7.0+）。  
   - 即使使用 `-p`，某些系统分区（如 `/system`）仍会强制使用默认权限。

5. **压缩传输的局限**  
   - `-z` 对已经压缩的文件（如 `.zip`、`.mp4`）提升不大，反而会增加 CPU 开销。  
   - 在极低带宽的 Wi‑Fi 环境下，压缩仍能显著降低传输时间。

6. **同步模式的兼容性**  
   - `--sync` 并非所有 ADB 发行版都实现，若出现 “unknown option --sync” 错误，请升级 Android SDK Platform‑Tools。

7. **大文件传输中断**  
   - 若传输过程中出现断电或 USB 失联，`adb push` 不会自动续传。需要重新执行命令或使用 `--sync` 进行增量复制。

8. **路径中的空格**  
   - 使用引号或转义字符包裹路径，例如：`adb push "My Docs/report.pdf" "/sdcard/My Docs/"`。

--- 

> **小技巧**：在批量部署时，可将多条 `adb push` 命令写入 `push_all.sh` 脚本，配合 `adb wait-for-device` 确保设备已准备好，再一次性执行，提升效率。
